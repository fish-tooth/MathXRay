# MathXRay 实验结果

2026-09-16。审查模型均为 Hy3。这份报告分开两块：公开的 ProcessBench，以及一份**不能外发的私有高中题集**。

---

## 1. 私有高中题集

题目来自本地文件 `data/high_school_all_annotated_final.json`（约 4300 道高中选择/填空，带官方详解和模型逐步解答）。仓库已 gitignore，不公开、不进远程。

这批数据**没有人工标注「哪一步开始错」**。我们只冻结了 88 道题（seed 42）做对照，并按来源拆开看，避免把四种情况混成一个数：

| 子集 | 条数 | 怎么判断对错 | 能看什么 |
|---|---:|---|---|
| 模型答案与参考答案不一致 | 28 | 答案错 ⇒ 过程至少有问题 | 能不能发现过程有错 |
| 模型答案与参考答案一致 | 28 | 过程好不好不知道 | 只看会不会乱判 |
| 官方详解 | 16 | 当作「过程大体正确」 | 会不会把对的过程打死 |
| 在官方步骤上改错 | 16 | 改哪一步是我们自己写进数据的 | 能不能指到被改的那一步 |

B0 是一次 JSON 判断。R1 是：先自己做一遍（看不到学生步骤）→ 逐段打 VALID/INVALID → 必要时指控/辩护 → 再汇总。学生答案和参考答案对不上时，R1 **不允许**再把过程说成成立。参考答案本身不会写进审查用的提示词。

### 结果（同一 88 条、同一模型）

| | B0 | R1 |
|---|---|---|
| 答案错误：发现过程有问题 | 4/28（0.14） | 28/28（1.00） |
| 改错样本：指到被改的那一步 | 11/16（0.69） | 12/16（0.75） |
| 官方详解：认为过程成立 | 7/16（0.44） | 6/16（0.38） |
| 上面两行的调和平均 | 0.54 | 0.50 |
| 答案正确样本被判过程错 | 4/28 | 5/28 |

答案错误那 28 条，R1 几乎是全抓到了，但拆开看：逐步审查自己标错的只有约 5 条；大约 18 条逐步仍认为每步都对，是「答案已经对不上」这条规则把它改判的。典型漏检是：题目要一个向量，解答停在 `(3λ,-4λ)` 这种参数族——等式局部成立，形式不完整。

改错 16 条上，R1 16 条都认为有错，12 条步号对上；其中只有 2 条是靠「答案对不上」才改判的，说明这条上找错步主要靠逐段审查。

官方详解上 R1 更严（10 条判错、6 条判对），所以调和平均略低于 B0。

### 这套数据说明什么

- 一次判断几乎看不见「写完了但没按题目要求收束」这类错。
- 用「答案已经错了」去卡过程，检出率会很高，但那不是「找到了第几步」。
- 逐段审查在我们自己改错的样本上有用，但对教材详解偏严。
- 私有集没有逐步对错的人工标注，**不能**拿它当 ProcessBench 那样的公开成绩单；它适合找失败模式、调提示词。

## 2. 公开评测（ProcessBench）

B0 在 GSM8K / MATH / Omni-MATH 切片上（n=244）：

| | 发现有错 | 首错步号一致 | 正确过程被接受 |
|---|---:|---:|---:|
| GSM8K（易） | 1.00 | 0.84 | 1.00 |
| MATH | 1.00 | 0.81 | 0.88 |
| Omni-MATH（难） | 0.95 | 0.75 | 0.77 |
| 三集合计 | 0.98 | 0.78 | 0.87 |

加上 OlympiadBench 后合计 n=349，首错步号一致约 0.75。难度上去，定位会掉。答案对但过程不对的样本，召回大约 0.91。

这是目前对外可以说的主数字。R1 还没有在 ProcessBench 上跑过，高中集上的 R1 不能外推到这里。

---

## 3. 结论和下一步

1. **公开集上，一次判断已经能较好地发现错误、中等好地指出第一步。** 难的是竞赛题上的定位，以及别把对的过程打死。
2. **私有高中集上，R1 更会抓「答案形式不对」，但对官方详解更挑剔，总账没有超过 B0。** 改进应放松逐步/指控，而不是再把「答案错必须过程错」收得更紧。
3. **应用上要让流程看得见**：独立求解 → 逐段（标出最早错误和后续跟着错的步骤）→ 必要时对质 → 汇总。看板要同时放公开集和私有集，并写清私有集不能外发。

本地原始记录在 `results/raw/`。公开数字以 `reports/official/` 为准。私有 JSON 不要提交。
